## Correct subscription lifecycle

From core `websocket_api/commands.py:748-843` and frontend `hui-markdown-card.ts:54-267`, `ws-templates.ts:34-52`:

- Store the subscription promise; one subscription per card instance.
- Subscribe in `connectedCallback` and after a content change; unsubscribe in `disconnectedCallback` and before any resubscribe (`.then(unsub => unsub()).catch()`).
- Params: `template: content`, `entity_ids: config.entities`, `variables: {config, user: hass.user.name}`, `strict: true` (config escape `strict: false`), `report_errors` true in editor preview and via a config key, `timeout` passthrough.
- Callback branches on `"error" in result`; render the error in-card instead of blanking. Rejected promise: show raw content, clear the handle so a later connect retries.
- Guard on an existing handle so reconnects never double-subscribe.
- Drop client-side entity tracking; the server tracks and pushes.

## The Yamaha face and shadow DOM

`shared/yamaha_display.yaml`: `ignore_line_breaks: true`, two entities, a `<style>` block with classes `.face .grid .label .value .vol`, custom props, clamp(), a 520 px media query, fonts `ledFont` and `displayFont`. Today the `<style>` lands in the view's shadow scope and its generic class names can collide with other cards.

`ledFont` and `displayFont` are declared nowhere under `~/workspace` or `~/repos`. Either a theme or CSS resource on the live instance declares them, or every browser has always fallen back to `ui-monospace, monospace`. Check on the instance before deciding the shadow DOM default:

```bash
grep -rn "ledFont\|displayFont\|@font-face" /config/themes /config/www /config/configuration.yaml
```

Shadow DOM: scoped styles, no collisions; `@font-face` declared at document level still resolves inside shadow DOM; theme CSS variables inherit. Cost: card-mod users need `$` piercing. Recommendation: `shadow: true` opt-in in Phase 3, default flipped only after the face is verified pixel-equivalent.

## Security

Trusted: `content` is admin config rendered by the admin's template engine. Untrusted: interpolated values (`source`, `sound_mode_raw`, device names, media titles). Jinja in HA does not autoescape, so a source string containing `<img src=x onerror=...>` runs in the admin session. `innerHTML` does not run `<script>` but does run event-handler attributes, `javascript:` URLs, iframes, SVG `onload`.

Sanitiser: DOMPurify cannot load from a CDN inside HA; bundle it (about 20 KB). Profile: `ADD_TAGS: ['style']`, `ADD_ATTR: ['class','style']`, forbid `on*`, block `javascript:`; allow `ha-icon`, `ha-svg-icon`, `ha-alert` with their attributes as HA's markdown does. This keeps the Yamaha face intact and strips handlers, script, iframe, object, embed, base, form. Default: sanitise on, `allow_unsafe_html: true` as a documented opt-out. Inline `style` can still exfiltrate via `url()` but cannot execute.
